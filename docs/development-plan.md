# AI 测试用例管理平台开发计划 v0.1

## 总体目标

从空项目开始，逐步实现一个 AI 测试用例管理平台。

第一阶段先实现 MVP，保证完整业务流程能跑通：

登录 → 创建项目 → 录入需求 → 生成测试用例 → 确认入库 → 查看用例

## 阶段 1：架构分析

目标：

- 理解参考项目整体结构
- 明确前端、后端、数据库、AI 模块职责
- 画出核心业务流程

产出：

- docs/architecture.md
- docs/development-plan.md

## 阶段 2：项目初始化

目标：

- 创建后端 FastAPI 项目
- 创建前端 React 项目
- 建立基础目录结构
- 跑通前后端服务

## 阶段 3：后端基础骨架

目标：

- 实现 FastAPI 应用入口
- 实现配置管理
- 实现数据库连接
- 实现健康检查接口

## 阶段 4：用户认证模块

目标：

- 实现用户模型
- 实现登录接口
- 实现 Token 鉴权
- 实现前端登录页

## 阶段 5：项目管理模块

目标：

- 创建项目
- 查看项目列表
- 编辑项目
- 删除项目

## 阶段 6：需求文档模块

目标：

- 新增需求文档
- 查看需求文档
- 保存需求原文
- 为后续 AI 拆分功能点做准备

## 阶段 7：功能点模块

目标：

- 从需求文档中拆出功能点
- 先使用 Mock 数据实现
- 后续接入真实 LLM

## 阶段 8：测试用例管理模块

目标：

- 定义测试用例数据结构
- 实现用例列表
- 实现用例新增、编辑、删除
- 支持从 AI 草稿入库

## 阶段 9：AI Mock 生成模块

目标：

- 根据功能点生成模拟测试用例
- 跑通 AI 生成流程
- 不依赖真实 API Key

## 阶段 10：真实 LLM 调用

目标：

- 设计 LLM 配置
- 封装模型调用服务
- 设计 Prompt
- 生成结构化测试用例

## 阶段 11：RAG 知识库模块

目标：

- 上传知识文档
- 文档分块
- 向量化
- 检索相关知识
- 注入 AI 生成上下文

## 阶段 12：测试任务执行模块

目标：

- 创建测试任务
- 添加测试用例
- 标记执行结果
- 统计通过率、失败数、阻塞数

## 阶段 13：前端页面整合

目标：

- 完成后台布局
- 完成路由
- 完成项目、需求、用例、任务页面
- 完成前后端联调

## 阶段 14：AI 助手与评测模块

目标：

- 实现项目问答助手
- 实现测试用例质量评测
- 实现生成效果对比
